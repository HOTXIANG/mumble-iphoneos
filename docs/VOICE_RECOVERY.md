# 语音与连接恢复

更新：2026-09-10

本轮目标是发现并恢复“连接仍在，但采集、播放或网络往返已经失效”。连接成功只在服务器完成加入后成立；音频健康要求采集和播放回调均持续完成，网络健康要求收到与本次探测匹配的心跳回复。

## 恢复行为

| 故障 | 检测与处理 |
| --- | --- |
| 采集或播放回调停止 | 每秒检查完成时间，任一方向超过 5 秒没有完成回调，显示语音恢复提示并重建音频设备。静音输出也计入完成，用户不说话不会触发误报。 |
| 设备启动失败 | 在仍有通话或本地测试请求时，以 1、2、4、8、16 秒上限的间隔重试。只有真实双向音频回调恢复后才报告健康。 |
| 系统音频中断、媒体服务重置、设备/路由切换 | 串行处理生命周期，合并连续路由变化；中断结束后按当前使用意图恢复。权限不可用或系统中断时显示对应提示。 |
| UDP 单向或双向失效 | 8 秒未收到匹配的 UDP 心跳回复时转 TCP 隧道，并重建/探测 UDP。普通下行语音和 TCP 隧道回复不能证明 UDP 上行健康。 |
| TCP 假在线 | 30 秒未收到匹配的 TCP 心跳回复时关闭旧连接并进入重连；其他服务器消息不会延长这个期限。 |
| TCP/TLS 握手不完成 | 20 秒超时。服务器未完成认证/同步在 30 秒超时。写队列 15 秒没有进展也会退出旧连接。 |
| 无网、Wi-Fi/蜂窝/有线切换 | 网络路径通知只用于判断何时尝试新连接，不再拆掉现有连接。现有连接由实际读写错误与心跳判断失效；已经断线且无网时等待路径恢复，恢复后仍遵守重连冷却时间。 |
| 已加入会话后长期掉线 | 连续失败的自动重连至少等待 5、15、30、60、120、300 秒，之后维持 300 秒。短暂加入不会重置这个计数，稳定连接满 60 秒后再失败才重新从 5 秒开始。首次加入始终失败仍按设置的次数终止。关闭自动重连会终止恢复。 |
| 用户取消、切换服务器、拒绝证书或不可恢复的认证失败 | 使旧准备任务、恢复计时器和回调失效。不会因旧任务完成而重新加入或开麦。 |

以上时间是检测阈值，不是端到端恢复时限。实际还受定时器调度、网络、服务器响应和设备初始化影响。

### 手机误断线回归修复

手机反馈进入服务器几秒后提示 `network changed` 并循环重连。上一轮路径监听把接口集合变化或默认路径暂时不可用直接转成连接错误，这会主动拆掉仍可使用的连接；仅有本地心跳失联测试未覆盖该路径。现已移除这个破坏性判断，保留实际传输健康检测，并增加上述自动重连限速，降低频繁登录触发服务器临时封禁的风险。服务器的具体封禁规则不同，客户端限速不能撤销已有封禁。

回归入口：`python3 Tests/recovery_review/real_app_heartbeat_probe.py --path-updates --retry-cooldown`。它在本地 TLS 会话上注入 15 次接口变化/暂时无路径，检查会话没有重新登录；随后停止真实心跳回复验证仍可重连，再主动关闭短暂重连后的会话，检查第二次恢复至少等待 15 秒。不会连接用户的服务器。

## 防止会话相互干扰

- 每次手动连接具有独立请求编号；自动重连沿用该编号。模型及传输实例另做身份检查，防止同一请求的旧重试影响新连接。
- 证书提示、延迟注册、连接遮罩、权限扫描、频道监听恢复均绑定当前请求或模型。频道监听状态按服务器、端口、用户名隔离。
- 切换传输会清理旧会话的语音包聚合、序号、播放缓冲和远程轨道。旧传输关闭不能清空新传输的音频绑定。
- 本地音频测试与通话音频启动/停止共用串行生命周期队列。离开设置页时保留正在建立或使用中的通话音频；取消麦克风请求后，迟到的权限回调不能再次开麦。
- TCP 支持分片读写、短写和暂时不可写；写队列、帧大小和语音积压设有上限，每轮读取最多处理 64 帧，给取消和健康检查留出执行机会。
- 清理服务器模型时先清空借用的当前用户指针，避免底层用户释放后 UI 仍读取它。

## 验证

2026-09-10 的整合版本已通过 iOS 设备目标无签名构建和 macOS Debug 构建。macOS 真实运行测试使用本机音频设备和回环地址，不连接外部用户，不保存或上传录音。

自动化检查入口：

```sh
sh Scripts/mumble_transport_native_check.sh
sh Tests/recovery_review/run_audio_health_tests.sh
sh Tests/recovery_review/run_audio_health_tests.sh --thread-sanitizer
sh Tests/recovery_review/run_swift_harness.sh
```

覆盖分片、短写、背压、EOF、错误、大小上限、读取公平性、重复/过期/乱序心跳、独立 TCP/UDP 往返、音频缓冲边界和并发时间戳。内存/未定义行为检查与音频并发检查均通过。Swift 测试直接编译生产 `ConnectionAsync.swift`，以替身控制器验证成功、错误、取消、替换和旧通知隔离，共 7 个场景。

运行空闲的 Debug 测试版并已有本地麦克风测试授权后，分别执行：

```sh
python3 Tests/recovery_review/real_app_health_probe.py --audio
python3 Tests/recovery_review/real_app_heartbeat_probe.py --audio
```

真实客户端已验证：

- 接受 TCP 但不回答 TLS 的本地端点按超时关闭，不被算作已连接。
- 连续取消连接后，连接和音频均停止。
- 主动停止真实设备回调后，健康状态变为恢复中，重建设备后恢复健康；停止测试会取消待执行恢复。
- 在已加入的本地会话中停止回调，频道使用的状态包含持续语音异常提示；恢复后提示清除。进入并退出音频设置后，通话音频仍保持健康。
- 连续 12 次本地音频测试启动/停止后，没有残留的音频运行请求，也不会被排队的旧启动再次打开麦克风。
- 本地 TLS 服务器持续发送用户状态但停止回应心跳：首轮实测继续收到 30 条下行消息，约 31.6 秒识别失联，随后自动重新加入。主动断开后连接和音频停止。

测试证据写入 `Tests/Artifacts/recovery-macos/`（被 Git 忽略）。TLS 测试生成临时自签名证书，只接受该回环地址端口的证书；应用会保存该测试端点的证书摘要和最近连接记录。测试结束恢复原有自动重连设置。音频故障注入接口仅存在于 Debug 构建。

全套旧自动化脚本仍被项目原有 `NeoMumble.icon` 资源一致性检查阻断；本轮未修改用户的图标配置。该问题与以上通过的独立测试和双平台构建分别记录。

## 验证边界

不能承诺任意条件下零中断。iOS 真机锁屏/长期后台、电话打断、蓝牙插拔、Wi-Fi 与蜂窝实际切换及多用户真实语音往返仍需要设备验收；构建和 macOS 回环测试不替代这些验收。

客户端回调与服务器心跳能证明本地音频处理和网络往返在前进，不能证明另一位用户的扬声器确实发声，也不能证明远端服务内部一定正确转发每个语音包。系统暂停或终止进程、权限被拒、服务器持续离线、硬件故障，以及第三方音频插件或设备停止函数永久阻塞，不能靠这些恢复逻辑保证即时恢复。
